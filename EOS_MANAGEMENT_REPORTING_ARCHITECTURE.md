# EOS Management Reporting Architecture

## Purpose
Define the recommended management-grade reporting structure around saved EOS snapshots.

## A. Report List Screen

Filters:
- period
- location
- clinic
- department
- generated by
- report type
- status
- date range

Output:
- compact table of saved snapshots

## B. Report Detail Screen

Sections:
- header
- summary
- rows
- audit

## C. Exception View

Separate from the normal report list.

Later filters:
- discrepancy present
- no walkout printed
- manager review pending
- emergency handover used
- superseded / abandoned shifts

## D. Period Dashboard

For management and month-end review:
- reports by period
- submitted vs not submitted
- discrepancies count
- unresolved manager reviews
- closed vs open periods

## E. Admin Summary Dashboard

Cross-cutting views:
- discrepancy events
- manager review outcomes
- pending queue items
- unresolved temporary closures

## Query Optimization Advice

For the list screen:
- use pagination from day one
- support `LIMIT` and `OFFSET` now
- consider keyset pagination later if list size grows

For the detail screen:
- use separate queries rather than a large join
- fetch rows only when a user opens a report
- do not preload detail rows for every list entry
